مانیتورهای آرکید CRT دارای ۳ پدیده مخرب هستند: ۱- اعوجاج پرسپکتیو و انحنای عدسی (Barrel Distortion) که خطوط راست را خمیده نشان می‌دهد. ۲- خطوط اسکن (Scanlines) که خطوط آبی ممتد دیوارها را منقطع می‌کنند. ۳- حاشیه تیره یا قاب آرکید که در برخی تصاویر با کانتور اصلی مارپیچ تداخل پیدا می‌کند.

اگر تنها به یک الگوریتم تقریب چندضلعی اتکا کنیم، در مواردی که نور کج تابیده یا اسکن‌لاین‌ها لبه‌ها را تکه‌تکه کرده‌اند، ۴ گوشه کادر اشتباه انتخاب شده و کل گرید ۴۰×۴۰ به هم می‌ریزد. بنابراین سیستم باید بتواند فرضیه‌های مختلف را بسازد و هوشمندانه بهترین را انتخاب کند.

hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV) blue = cv2.inRange(hsv, (90, 100, 100), (135, 255, 255)) # پر کردن شکستگی‌های ناشی از Scanlines با کرنل مورفولوژی ۱۱×۱۱ blue = cv2.morphologyEx(blue, cv2.MORPH_CLOSE, np.ones((11, 11), np.uint8))

گام ۲: تولید نگاشت کاندیدای اول (Quad Perspective)

بزرگ‌ترین کانتور با شرط مساحت بالای ۵٪ مساحت کل تصویر گرفته شده و پوش محدب (Convex Hull) آن محاسبه می‌شود. سپس با الگوریتم Ramer-Douglas-Peucker در دامنه‌ای از ۷ مقدار اپسیلون مختلف جستجو می‌شود:

for eps in (0.02, 0.03, 0.05, 0.08, 0.1, 0.15, 0.2): ap = cv2.approxPolyDP(hull, eps * peri, True) if len(ap) == 4: return order_quad(ap.reshape(4, 2)) # در صورت نیافتن ۴ضلعی دقیق، از مستطیل حداقل زاویه‌دار استفاده می‌شود return order_quad(cv2.boxPoints(cv2.minAreaRect(hull)))
گام ۳: نگاشت کاندیدای دوم و نوآوری معیار tree_clarity

نگاشت دوم (Bbox Warp) مستقیماً از مستطیل محاطی بزرگ‌ترین کانتور استفاده می‌کند. حال کدام تصویر انتخاب شود؟ تابعی به نام tree_clarity تعریف شده که ماتریس اطمینان دیوارها را بررسی می‌کند:

def tree_clarity(cR, cD): v = np.concatenate([cR.flatten(), cD.flatten()]) # دیوارهای باکیفیت مقادیر بسیار نزدیک به 0 (نبود دیوار) یا بسیار نزدیک به 1 (دیوار قطعی) دارند return float(((v < 0.15) | (v > 0.70)).mean())
✓
شرط تصمیم‌گیری قطعی: اگر tree_clarity > 0.5 باشد، نگاشت پرسپکتیو ۴ نقطه‌ای اعمال می‌شود؛ در غیر این صورت سیستم خودکار به نگاشت Bbox سوئیچ می‌کند تا از کج شدن گرید جلوگیری کند.
ماژول ۲: نظریه گراف و بازسازی مارپیچ

بازسازی قطعی مارپیچ با درخت پوشای بیشینه (Kruskal MST)

چرا آستانه‌گذاری ساده دیوارها شکست می‌خورد و چگونه الگوریتم کروسکال پیوستگی ۱۰۰٪ را تضمین می‌کند؟

چرا آستانه‌گیری ساده دیوارها شکست می‌خورد؟

یک رویکرد خام ممکن است بگوید: «اگر در مرز دو سلول پیکسل آبی دیدیم، دیوار است؛ وگرنه راه باز است». اما در تصاویر CRT این رویکرد به دو فاجعه منتهی می‌شود:

  • تار شدگی نور نئون (Neon Bloom): درخشش نور نئون در راهروهای باریک خالی پخش می‌شود و پیکسل‌های آبی کاذب ایجاد می‌کند؛ در نتیجه یک معبر کاملاً باز، مسدود تشخیص داده می‌شود و بن‌بست کاذب پدید می‌آید.
  • برش خطوط اسکن CRT: یک خط اسکن سیاه ممکن است درست از وسط یک دیوار آبی عبور کند؛ سیستم آستانه‌گیر فکر می‌کند دیوار سوراخ است و دورهای کاذب (Cycles) در گراف پدید می‌آورد.

در چنین شرایطی، الگوریتم‌های مسیریابی یا در حلقه‌های بی‌نهایت گیر می‌افتند یا مسیری اشتباه از میان دیوارهای بسته پیدا می‌کنند.

گام ۱: محاسبه ماتریس‌های اطمینان پیوسته (cR و cD)

برای حل این مشکل، به جای تصمیم‌گیری باینری صفر و یک، از ماتریس اطمینان احتمالاتی استفاده می‌کنیم. ابتدا فیلتر گوسی با هسته 5×5 نویزهای تک‌پیکسلی را هموار می‌کند. سپس نوار مرزی ۷ پیکسلی با پدینگ ۸ پیکسل از لبه‌ها نمونه‌برداری می‌شود:

# دیوار عمودی سمت راست سلول (cR) x = (c + 1) * CELL strip_R = blue[r*CELL+pad:(r+1)*CELL-pad, max(0, x-3):min(W, x+4)] cR[r, c] = float(strip_R.max(axis=1).mean()) # دیوار افقی پایین سلول (cD) y = (r + 1) * CELL strip_D = blue[max(0, y-3):min(H, y+4), c*CELL+pad:(c+1)*CELL-pad] cD[r, c] = float(strip_D.max(axis=0).mean())
فرمولاسیون ریاضیاتی Kruskal با داده‌ساختار DSU
قید ساختاری «مارپیچ کامل (Perfect Maze)»

طبق مشخصات بازی مینی پک‌من، مارپیچ کامل است. از منظر نظریه گراف، یک شبکه با V = 15 × 21 = 315 سلول، دقیقاً و حتماً دارای E = V - 1 = 314 یال باز بدون هیچ‌گونه دور (Cycle) است. این قید به این معناست که مارپیچ ذاتاً یک «درخت پوشا (Spanning Tree)» است!

گام ۲: اجرای الگوریتم Kruskal با وزن معکوس اطمینان دیوار

وزن هر یال به عنوان «احتمال باز بودن مسیر» تعریف می‌شود: W = 1.0 - wall_confidence. تمام یال‌های کاندیدا به ترتیب نزولی وزن مرتب می‌شوند تا معابری که مطمئن‌تر هستند زودتر انتخاب شوند:

edges = [] # اضافه کردن تمام یال‌های افقی و عمودی با وزن معکوس دیوار edges.append((1.0 - cR[r, c], node_i, node_i + 1)) edges.append((1.0 - cD[r, c], node_i, node_i + COLS)) edges.sort(reverse=True) # بیشترین احتمال باز بودن معبر # الگوریتم کروسکال با داده‌ساختار مجموعه مجزا (DSU) used_edges = 0 for weight, u, v in edges: if find(u) != find(v): union(u, v) graph[u].append(v); graph[v].append(u) used_edges += 1 if used_edges == V - 1: break # انتخاب ۳۱۴ یال همبند
تضمین ریاضی پیوستگی: الگوریتم Kruskal تضمین می‌کند که ۱- هیچ دوری در گراف شکل نگیرد، ۲- گراف کاملاً همبند باشد، ۳- بین هر دو سلول مارپیچ دقیقاً یک مسیر پیوسته و یکتا وجود داشته باشد.

چرا BFS روی ساختار درختی کوتاه‌ترین مسیر یکتا را به دست می‌دهد و دانه‌ها چگونه محاسبه می‌شوند؟

الگوریتم BFS معکوس روی گراف درخت پوشا

هدف اصلی بازی، حرکت پک‌من به سمت گیلاس است. ما باید دنباله دقیق حرکات را به صورت رشته‌ای از حروف 'U' (بالا)، 'D' (پایین)، 'L' (چپ) و 'R' (راست) استخراج کنیم.

مزیت فوق‌العاده ساختار درخت: در یک گراف دارای دور، الگوریتم‌های مسیریابی ممکن است در حلقه‌ها بیفتند یا نیاز به الگوریتم‌های پیچیده وزن‌دار مثل Dijkstra داشته باشند. اما چون گراف مارپیچ ما یک درخت پوشا است، بین هر دو راس دقیقاً یک مسیر پیوسته یکتا بدون هرگونه دور وجود دارد! بنابراین BFS ساده‌ترین، سریع‌ترین و کوتاه‌ترین مسیر قطعی را پیدا می‌کند.
کدگذاری جهت‌ها (Direction Encoding)

جستجو از گیلاس آغاز شده و تا پک‌من ادامه می‌یابد. سپس زنجیره سلول‌ها به حروف جهت‌ها ترجمه می‌شود:

cells = bfs_path(graph, start=cherry, goal=pac) path_chars = [] for (r1, c1), (r2, c2) in zip(cells, cells[1:]): dr, dc = r2 - r1, c2 - c1 if dr == -1 and dc == 0: path_chars.append('U') elif dr == 1 and dc == 0: path_chars.append('D') elif dc == -1 and dc == 0: path_chars.append('L') elif dr == 0 and dc == 1: path_chars.append('R') path_str = "".join(path_chars)

path_set = set(cells) n_pellets = sum(1 for c in pellets if c in path_set and c != pac and c != cherry) final_score = initial_score + (n_pellets * 10) + 100
